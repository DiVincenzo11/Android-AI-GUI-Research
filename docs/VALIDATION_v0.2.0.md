## 发现并修正的问题

- 原启动实现使用 Monkey；现改为解析 launcher activity 后 `am start -W`，前台已为目标包时不额外发随机事件。
- PocketPal 后台释放模型和首次模型选择器需要多步操作；加入有上限、精确定位的步骤，不覆盖未知输入。
- 流式 UI / WebView 期间 shell dump 可能缺失 hierarchy。默认后端加入有限重试；显式可选 UIAutomator2 后端配置空闲等待 0，并记录使用的后端。
- 回答正文常没有唯一资源 ID。增加回答祖先容器或角色标签约束，排除包含完整提示词的回显，保留稳定两次采集检查。
- Duck.ai 首轮与续聊的发送按钮不同，提供两个分别验证的配置；不把缺失按钮当作已发送。
- ChatterUI 回答带双向文本控制符，旧 Windows 控制台打印曾失败。证据文件当时已保存，现控制台输出转义 JSON，UTF-8 原始证据不变。

## 不能据此声称

没有独立冻结测试集上的入口精确率、召回率、跨应用成功率、模型能力或语义质量评测。应用、版本和适配器是在开发中选择与调试的；最终 3 个案例通过不是全部尝试通过。公开记录包含失败和改动过程。

本轮没有执行完整 ScenGen、自动登录、付费调用、物理手机验证或大规模应用探索。模型和首次介绍依赖人工准备，主路径使用配置指定的精确控件；不应写成自主发现并完成任意 AI 功能。
